1. Overview & Purpose

J Voice is a bilingual (Telugu/English) regional news + competitive-exam-prep platform. The web/ folder is not the public product's mobile experience — it is the staff console (news desk + study content authoring) plus a lightweight public reader website, sharing one Firebase backend with the Android app.

2. Tech Stack

Frontend

  • React 18.3 + Vite 5.4 (plain JS, no TypeScript)
  • react-router-dom 6.26
  • Hand-rolled reducer + Context state (no Redux/Zustand)
  • One global styles.css (CSS variables, light/dark) + separate reader/reader.css
  • Custom bilingual {en, te} value type (i18n/localized.js) — mirrors Android's LocalizedText

Backend & tooling

  • Firebase JS SDK 12.18 — Auth, Realtime Database, Firestore
  • Separate firebase/ package (firebase-admin) for rules + seed scripts
  • build-standalone.mjs — hash-routed single-file build
  • Playwright smoke.mjs end-to-end smoke test
  • Hosting via root firebase.json (serves web/J Voice web/dist)

4. Firebase Integration

Auth

Email/password. Staff type a bare username → expanded to username@jvoicenews.com. Demo persona buttons (no password) coexist with real sign-in in the same AuthProvider.

Realtime Database

users/{uid} (role, isLogin kill-switch, forceLogoutAt, lastLoginAt), flags/{key} (world-readable), failedLoginAttempts, passwordResetRequests.

Firestore

articles, categories, subjects, topics, studyArticles, questions, exams, examTracks. Role checks use a custom auth claim, not a document read.

Security rules (firebase/database.rules.json, firebase/firestore.rules) are default-deny, with role writable only by super_admin, and anonymous readers scoped to published content only. This is the same Firebase project the Android app uses — see the audit report for how well the two clients agree on schema.

Route gating (App.jsx) uses only four hardcoded personas (Admin/Editor/Reporter/Content Creator) — the granular Roles permission matrix UI has no functional effect on this gating (see Known Issues).

6. State Management & Data Flow

  • Single reducer(state, action) handles ~50 action types; every mutation also appends a line to state.activity (the session log).
  • initialState starts empty for everything Firestore-backed — populated only after sign-in via useFirestoreSync hydration.
  • users, settings, roles, templates, shorts are seeded from local mock files and never synced to any backend — they reset on reload.
  • Console writes go back to Firestore via a diff against a recorded baseline (syncCollection) rather than one handler per action type.
  • The public reader uses a completely separate, read-only listener set (reader/publicFeed.js) — it never touches the console's store.

7. Brand Assets

Single source of truth lives in top-level brand/: jvoice-logo-source.jpg + make_assets.py (a Pillow script that flood-fills the black background from the edges inward, using a max-channel test to avoid making the navy wordmark plate translucent). It regenerates assets for both the Android app and the web app's public/ folder.

Palette: scarlet #DD0B1E, royal blue #17318F, navy #0D1F63, silver #E9ECF1. Deliberate divergence: the console's UI accent uses blue, not scarlet — scarlet is already --danger, and reusing it for "current page" would collide with "delete".

9. Known Issues (verified in code)

Article body/description silently blanked on Firestore round-trip

Console UI (News.jsx, MyStories.jsx) reads/writes headline, description, body. The Firestore codec that actually syncs articles (firestoreData.js) uses headline, shortDescription, content — matching the Android schema, not the console UI. Result: description/body are undefined → written as blank {en:'', te:''}. The public reader (which correctly reads shortDescription/content) will show a blank standfirst and body for any console-authored article.

src/pages/News.jsx, src/pages/MyStories.jsx vs src/store/firestoreData.js (CODECS.articles)

Same class of bug for Categories/Subjects/Topics/Exam Types

Management pages read/write plain nameEn/nameTe fields; the Firestore codecs for these four collections use a single bilingual name: {en, te} field. Once Firestore hydration replaces local state, these editing UIs render blank names and edits write garbage back.

src/pages/News.jsx (Categories), src/pages/Study.jsx (Subjects/Topics/ExamTypes) vs src/store/firestoreData.js

Exam "blueprint" dropped on Firestore sync

Exams.jsx's exam objects carry a blueprint array driving the paper editor, bank-coverage checks and preview. The Firestore codec for exams has no blueprint field — any exam re-hydrated after reload loses its blueprint, breaking the editor and paper preview.

src/pages/Exams.jsx vs src/store/firestoreData.js

Reporter picker in "New article" always empty

state.users.filter(u => u.role === 'Reporter') — but user records only ever have a roles array. No user object has a singular .role, so this filter always returns nothing.

src/pages/News.jsx

Roles permission matrix is decorative

The fine-grained CRUD permission editor has no effect on actual access control — route gating checks only the four hardcoded personas, and real backend security is enforced separately via Firebase custom claims.

src/pages/Roles.jsx vs src/App.jsx (AdminOnly, Allow)

Two separate "feature flag" systems

System.jsx Settings toggles are purely in-memory and read by nothing else. FeatureFlags.jsx is a separate, real RTDB-backed set the Android app actually reads. Visually similar, easy to confuse when demoing or documenting.

src/pages/System.jsx vs src/pages/FeatureFlags.jsx

Real staff account with no matching mock user row → blank dashboard

useMe() resolves "me" by matching username/email against the local mock users array. A real account provisioned purely via seed-staff.mjs/RTDB with no corresponding mock row gets a blank Editor/Creator/Reporter dashboard (they return null) even though sign-in succeeded.

src/pages/RoleDashboards.jsx

Dead seed imports

Several seed* imports from data/newsData.js/data/studyData.js are imported into store.jsx but never used — leftover from before Firestore sync replaced local seeding. A fresh/newly-provisioned console shows an empty catalogue until seed scripts are run or content is authored live.
